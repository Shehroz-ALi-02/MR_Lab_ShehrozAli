# Brief Description
This lab focused on implementing Reactive Navigation for a TurtleBot3 Burger within a Gazebo simulation environment using LiDAR data. The primary objective was to move away from pre defined paths and instead use the /scan topic to perceive the environment in real time. I developed a ROS 2 Python node that processes LaserScan data to implement three core behaviors: Obstacle Detection (stopping before a collision), Obstacle Avoidance (turning toward the clearest path), and Wall Following (using proportional control to maintain a fixed distance from a boundary).

# Commands Used
**Simulation & Environment Setup**

export TURTLEBOT3_MODEL=burger: Set the robot model to the Burger variant.

ros2 launch turtlebot3_gazebo turtlebot3_world.launch.py: Launch the TurtleBot3 simulation in the standard Gazebo world.

ros2 run rviz2 rviz2: Open RViz to visualize the LaserScan points and robot transform.

**Data Monitoring & Execution**

ros2 topic list: Verify that /scan and /cmd_vel topics are active.

ros2 topic echo /scan: Monitor raw distance data from the 360-degree LiDAR sensor.

ros2 run my_turtle_package lidar_navigator: Execute the custom reactive navigation node.

ros2 topic echo /cmd_vel: Check the velocity commands being generated by the navigation logic.

# Problems Faced and Solutions
**Issue 1: Math Errors due to "inf" and "NaN" Values**

Problem: The LiDAR sensor returns inf (infinity) for areas where no obstacles are detected within range. This caused the navigation logic to crash when performing minimum distance calculations or comparisons.

Solution: Used numpy to clean the data array, replacing all inf values with the maximum sensor range and NaN values with zero before processing the regions.

**Issue 2: Angular Jitter and Oscillations**

Problem: When the robot was in a corner, it would rapidly alternate between "Turn Left" and "Turn Right" commands, causing the robot to shake in place without moving forward.

Solution: Implemented a dead-band for the turning logic and used the average distance of a 60-degree "slice" rather than a single laser beam to make the decision-making more robust against sensor noise.

**Issue 3: High-Speed Collisions**

Problem: At default speeds, the robot’s inertia caused it to hit walls even after the "Stop" command was issued because the threshold was too small.

Solution: Adjusted the front_threshold to 0.5m and reduced the linear velocity to 0.15m/s, allowing the robot enough braking distance to stop safely.

# Reflection
This lab marked a significant shift from "Open-Loop" control to "Closed-Loop" Reactive Control. Unlike the previous lab where I moved the turtle to fixed coordinates, this lab required the robot to make autonomous decisions based on external stimuli. I learned how to slice a 360-element array into functional "viewing regions" (Front, Left, Right) to give the robot spatial awareness. This "Sense-Act" paradigm is fundamental to robotics, as it allows machines to operate in dynamic, unknown environments where pre-calculated paths are not possible. Dealing with noisy LiDAR data also highlighted the importance of data filtering and threshold tuning in real-world robotics applications.
